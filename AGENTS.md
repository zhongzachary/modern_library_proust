# AGENTS.md

## Project purpose

This repository is a small, static reader aid for the 2003 Modern Library
six-volume paperback edition of Marcel Proust's *In Search of Lost Time*.
It contains transcribed companion material, derived search data, and a
no-build browser interface. Treat the text as editorial content: preserving
spelling, punctuation, page references, and Markdown structure is more
important than normalizing prose.

## Repository layout

- `index.html` - self-contained GitHub Pages interface. It loads DuckDB-Wasm
  from a CDN and queries `a_guide_to_proust.parquet` in the browser.
- `a_guide_to_proust.parquet` - generated search dataset consumed by the UI.
- `raw_text/a_guide_to_proust.md` - canonical raw source for the guide.
- `formatted_guide_to_proust.md` - generated, readable Markdown form of the
  guide.
- `raw_text/synopses.md` - separately maintained source text; it is not read
  or generated by the Python parser.
- `python/parse_raw_text.py` - parser and generator for the formatted guide
  and Parquet dataset.
- `python/pyproject.toml` and `python/uv.lock` - Python 3.13+ environment,
  managed with `uv`.

## Data workflow

`raw_text/a_guide_to_proust.md` is the source of truth for the guide. From
the `python/` directory, run:

```sh
uv run parse_raw_text.py
```

The script relies on its current working directory because its input and
output paths are relative. It rewrites both of these repository-root files:

- `formatted_guide_to_proust.md`
- `a_guide_to_proust.parquet`

Commit regenerated artifacts whenever the raw guide or parser changes. Do not
hand-edit those generated files unless the task is explicitly to correct a
generated artifact and its source cannot be changed.

The raw guide format is part of the parser contract: top-level `#` headings
define sections, entries are separated by blank lines, and lines beginning
with `_` are parsed as super-entries. Preserve that structure when correcting
transcriptions. Keep page references, Roman volume labels, and `--` page/year
ranges exactly as printed unless fixing a known transcription error.

## Frontend workflow

There is no Node build, package manifest, or test suite. `index.html` is the
application and expects the Parquet file to be available at the site root.
For local browser checks, serve the repository root rather than opening the
file directly:

```sh
python3 -m http.server
```

The UI builds SQL strings against the Parquet schema. When changing parser
columns, update `index.html` in the same change and verify entry-name and
page searches in a browser. Keep the page dependency-free and avoid adding a
build tool unless the task specifically warrants one.

## Frontend design direction

The interface should feel like a quiet, book-oriented reference tool rather
than a marketing page or generic dashboard. Preserve the established
editorial character: warm paper and ink colors, a restrained deep-red accent,
serif typography for reading, and system sans-serif typography for controls.

Keep search as the primary experience and favor compact, clearly grouped
controls over decorative sections or card-heavy layouts. New UI should match
the existing visual language before introducing new patterns. Maintain
keyboard access, visible focus and error states, readable contrast, and a
responsive layout down to the existing 320px minimum width. Avoid changes
that cause text, controls, or result content to overlap or shift unexpectedly.

These are durable guardrails, not a requirement to preserve every current CSS
value. If a task intentionally establishes a new design direction, update this
section along with the implementation.

## Change and validation guidance

- Keep corrections narrowly scoped and retain the project’s editorial tone.
- Regenerate outputs after parser or raw-guide edits, then review the Markdown
  diff and confirm the Parquet file changed as expected.
- After dependency changes, update and commit `python/uv.lock`.
- For HTML, data, or parser changes, run `git diff --check` and perform the
  relevant local browser or generator check.
- Do not modify unrelated generated data or reformat source text wholesale.
- The repository is an unofficial, noncommercial reader aid. Keep its
  copyright and attribution language intact unless explicitly asked to change
  it.
